# ADR-0001: 技術スタックに Tauri v2 + Svelte を採用

- ステータス: 採用
- 日付: 2026-06-23
- 決定者: 作者（dekka）

## コンテキスト

軽量なクロスプラットフォーム・デスクトップアプリ（ポモドーロタイマー）を作り、公開リポジトリで
配布したい。要件の核は「軽量であること」「常駐・最前面表示・トレイ的な常時表示ができること」
「Windows / macOS / Linux で動くこと」。開発主環境は Windows・WQHD。

## 検討した選択肢

1. **Tauri v2（Rust + WebView）** — OS の WebView を使う軽量フレームワーク。
   - 長所: バイナリ ~3-10MB・低メモリ、クロスプラットフォーム、最前面/常駐の制御が充実、
     公開・配布との相性が良い。
   - 短所: Rust の知識が少々必要。WebView 差異の考慮が要る場合がある。
2. **.NET（WPF / Avalonia, C#）** — ネイティブ寄り。
   - 長所: 常駐・最前面のネイティブ API が使いやすい、実績豊富。
   - 短所: WPF は Windows 限定（クロスプラットフォームは Avalonia 要）、バイナリは中程度。
3. **Electron（TypeScript/JS）** — Chromium 同梱。
   - 長所: Web 技術だけで書けて学習が楽。
   - 短所: バイナリ ~50-150MB・メモリ高。「軽量」要件と相反する。

## 決定

**Tauri v2 + Svelte（Vite / TypeScript）+ pnpm / cargo** を採用する。
フロントエンド UI は **Svelte**、コアロジック（タイマー進行・サイクル状態管理）は **Rust** 側に置く。
通知音は WebView の HTML5 Audio で再生する。

## 理由

最重要要件が「軽量 + クロスプラットフォーム + 公開」であり、Tauri がこの 3 点に最も合致する。
Electron は軽量要件に反するため除外。.NET は有力だが、クロスプラットフォーム前提だと Avalonia が
必要で、Tauri のバイナリ軽さ・配布のしやすさに比べ利点が薄い。UI はこの規模ならフレームワーク無しでも
書けるが、状態（フェーズ/残り時間/設定）の管理が読みやすくなる軽量フレームワークとして Svelte を選んだ。

## 結果と影響

- ポジティブな影響:
  - 小さいバイナリ・低メモリで「軽量」要件を満たせる。
  - 1 コードベースで Windows / macOS / Linux 向けインストーラを生成できる。
- ネガティブな影響・トレードオフ:
  - Rust と Web フロントの 2 言語を扱う必要がある。
  - 最前面・ウィンドウ位置/サイズ制御で OS ごとの WebView 挙動差に注意が要る場合がある。
- 将来の見直しトリガー:
  - ネイティブにしか出せない挙動（特殊な最前面制御等）が必要になった場合は .NET/ネイティブを再検討。
