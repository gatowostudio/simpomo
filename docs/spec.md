# Specification — simpomo

シンプルで軽量なポモドーロタイマー（デスクトップアプリ）の機能要件・非機能要件。

## 概要

作業に集中するためのポモドーロ・テクニックを支援する常駐型タイマー。画面の隅に小さく表示され、
基本は常に最前面に出続ける。多機能化せず「邪魔にならず、見やすく、軽い」を最優先する。
クロスプラットフォーム（Windows / macOS / Linux）で動作し、GitHub Releases でインストーラを配布する。

## 機能要件

### コア機能（MVP）

- [ ] **常駐タイマー表示**: 起動すると画面の隅にコンパクトに表示。残り時間と現在フェーズ
      （作業 / 休憩）が一目でわかる。
- [ ] **表示位置の設定**: デフォルトは右上。設定で四隅などから位置を選べる。
- [ ] **always-on-top（最前面）**: 基本は常に最前面。ボタン一つでこのモードを ON/OFF 切替可能。
- [ ] **作業/休憩時間のカスタム**: デフォルト 作業25分 → 休憩5分。設定で各時間を変更可能。
- [ ] **サイクル数の設定（= 自動継続するサイクル数）**: 0〜無限で設定可能。
      - **0（デフォルト）**: 作業→休憩を1セット実行したら停止。次は start ボタンを押すまで開始しない（手動）。
      - **有限 N**: N セットを自動で連続実行し、終わったら停止。
      - **無限**: start を押さずとも次のサイクルが自動で始まり続ける。
- [ ] **通知音の選択**: タイマー（作業）終了音・休憩終了音をそれぞれ設定で選択可能。
      シンプルな音をいくつか同梱（ロイヤリティフリー/自作のみ）。
- [ ] **ウィンドウサイズのプリセット**: 画面解像度を加味した複数サイズから選択。
      デフォルトは「邪魔にならないが見づらくない」サイズ。
- [ ] **設定画面**: 上記の各設定を変更・永続化できる UI。

### 拡張機能（MVP 後）

- [ ] 一時停止 / リセット / スキップ操作（必要に応じて）
- [ ] 起動時自動スタート / OS スタートアップ登録
- [ ] サイクル完了数の簡易統計表示
- [ ] オートアップデータ（Tauri updater、署名鍵の管理が前提）

## 非機能要件

- **パフォーマンス / 軽量性**: 重量級依存を持ち込まない。アイドル時のメモリ・CPU を最小に保つ。
  Tauri による小さいバイナリを維持する。
- **可用性**: オフライン完結。ネットワーク不要で常時動作。
- **セキュリティ / 公開対応**: 公開リポジトリ。機密情報（署名鍵・updater 秘密鍵・`.env`）を
  コミットしない。同梱する音源は著作権上問題のないもののみ。
- **アクセシビリティ**: 小さい表示でも残り時間が判読できるコントラスト/フォントサイズ。

## 制約

- クロスプラットフォーム（Windows / macOS / Linux）で破綻しない実装にする。
- 開発主環境は Windows・WQHD (2560x1440)。ウィンドウサイズは解像度に応じて算出する。
- 配布形態は GitHub Releases のインストーラ/実行ファイル。

## 画面一覧

- **メイン（タイマー）画面**: 残り時間・フェーズ表示、最前面トグルボタン、（拡張で）開始/停止。
- **設定画面**: 表示位置・作業/休憩時間・サイクル数・通知音・ウィンドウサイズ。

## オープン課題

- [x] 通知音は Web Audio API による合成音（自作・同梱ファイルなし）に決定。出典は `docs/credits.md`。
- [ ] ウィンドウサイズプリセットの具体値の調整（現状は固定論理pxの 6 段階。実機で見え方を確認して微調整）。
- [ ] 下側の隅（BottomLeft/BottomRight）選択時のタスクバー重なり対策（work area 対応）。#5 で位置選択を出すときに対応。
- [ ] ユーザーがドラッグ移動した位置の保存・復元（現状は起動ごとに既定の隅へ）。#5 永続化と併せて検討。
- [ ] マルチモニタ構成変更・解像度/スケール変更時の再配置追従。
- [ ] 二重起動の防止（single-instance）。常駐ツールとして要否を検討。
- [ ] 通知音を 3 OS 実機で試聴し音量/音色を確認（WebView 差: Windows=WebView2 / mac=WKWebView / Linux=WebKitGTK）。
- [ ] 「起動時自動スタート」（拡張機能）導入時、ユーザー操作前の初回再生が autoplay でブロックされない方策。
- [ ] OS トースト通知（ウィンドウ非表示中の視覚通知）の要否。現状は通知音のみ。
- [ ] コード署名（Windows SmartScreen / macOS Gatekeeper 対策）。現状インストーラは未署名で初回起動時に
      警告が出る。費用（Apple Developer / Windows 証明書）が要るため MVP では見送り、導入時に鍵を Secrets 管理。
